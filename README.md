# 先正电子寄售取数 - 配置化工具包

## 📁 文件结构

```
先正寄售取数/
├── 先正寄售取数_config.yaml    ← 核心配置文件（唯一需要修改的文件）
├── render_sql.py               ← SQL 渲染脚本（读取配置 → 生成 SQL）
├── validate_config.py          ← 配置校验脚本（生成 SQL 前先检查）
├── README.md                   ← 本说明文档
└── output_sql/                 ← 生成的 SQL 文件输出目录
    ├── 01_本月收到_调拨单.sql
    ├── 02_本月收到_发货退货单追加.sql
    ├── 03_本月开票数指标表.sql
    ├── 04_收到表_分组回填.sql
    ├── 05_开票表_分组回填.sql
    ├── 06_本月未开票汇总表.sql
    ├── 07_开票退补表.sql
    ├── 08_收到_存货编码汇总.sql
    ├── 09_收到_分组存货编码汇总.sql
    ├── 10_开票_存货编码汇总.sql
    ├── 11_二维码读入说明.sql
    └── 配置校验报告.txt
```

## 🚀 快速开始

### 1. 修改配置

用记事本或任意编辑器打开 `先正寄售取数_config.yaml`，修改对应配置项。

### 2. 校验配置（推荐）

```bash
python validate_config.py
```

检查配置中是否有重复客户、孤儿分组、日期错误等问题。

### 3. 生成 SQL

```bash
python render_sql.py
```

自动生成 11 段 SQL 到 `output_sql/` 目录，按序号顺序执行即可。

## ⚙️ 配置说明

### meta - 全局参数

| 字段 | 说明 | 示例 |
|------|------|------|
| version | 表版本号后缀 | "0630"（6月30日版本） |
| period_full | 完整期间格式 | "2026-06" |
| period_short | 短期间格式 | "2026-6" |
| date_start | 开始日期 | "2026-06-01" |
| date_end | 结束日期 | "2026-06-30" |
| consign_flag_field | 寄售标识字段 | "ccusdefine2" |
| consign_flag_value | 寄售标识值 | "T" |
| cust_item_no_expr | 客户料号取值表达式 | ISNULL(NULLIF(cdefine28,''), cCusInvCode) |

### consign_points - 寄售点客户

分为两类来源：
- **transfer**：调拨单来源（TransVouch 表）— 19 家
- **dispatch**：发货退货单来源（DispatchList 表）— 33 家

每个客户可配置：
```yaml
- name: "客户名称"    # 必填，客户档案中的全称
  code: "客户编码"    # 选填，客户编码
```

**新增寄售点步骤：**
1. 判断该客户是走调拨单还是发货退货单
2. 在对应列表中添加客户名称
3. 如果属于某个集团，在 group_mapping 中添加分组成员
4. 如果有特殊开票规则，在 invoice_rules 中配置
5. 如果是二维码扫码客户，在 qrcode_customers 中添加

### group_mapping - 集团分组

用于按集团汇总统计，每个分组包含多个成员客户。

```yaml
- group_name: "集团名称"
  members:
    - name: "客户名称"
      scope: "both"    # both=收到+开票都算 / received=仅收到 / invoiced=仅开票
```

**scope 业务规则：**
- **重庆海尔**：收到只算物流公司（调拨单为准），开票算物流+空调器
- **佳世达**：收到只算电通公司（调拨单为准），开票算电通+电子
- 其他分组：通常都是 both

### invoice_rules - 开票规则

#### special_memo_customers - 特殊开票备注客户

某些客户必须满足特定备注条件才计入开票汇总。

```yaml
- name: "客户名称"
  memos:
    - "备注值1"
    - "备注值2"
```

示例：南京国电南自必须备注是"开发货单专用"或"销账 寄售"才计入开票。

#### summary_exclude_customers - 开票汇总排除清单

这些客户不参与通用开票汇总（有单独规则或单独统计）。

### qrcode_customers - 二维码读入客户

这些客户的客户料号通过扫码读入到指定字段。

```yaml
enabled: true
scan_field: "cdefine31"      # 扫码读入字段
fallback_field: "cCusInvCode" # 空值回退字段
customers:
  - "客户名称1"
  - "客户名称2"
```

## 🔍 校验项说明

`validate_config.py` 会检查以下 12 项：

| # | 校验项 | 级别 | 说明 |
|---|--------|------|------|
| 1 | 重复客户检查 | ❌错误 | 同一客户同时出现在调拨单和发货退货单 |
| 2 | 重复客户编码检查 | ❌错误 | 不同客户使用相同编码 |
| 3 | 孤儿分组成员检查 | ⚠️警告 | 分组成员不在寄售点列表中 |
| 4 | 未分组客户检查 | ℹ️提示 | 寄售点客户没有归属分组 |
| 5 | 特殊开票客户缺失 | ⚠️警告 | 特殊开票客户不在寄售点列表 |
| 6 | 开票排除客户缺失 | ⚠️警告 | 排除清单客户不在寄售点列表 |
| 7 | 二维码客户缺失 | ⚠️警告 | 二维码客户不在寄售点列表 |
| 8 | 客户编码空值检查 | ℹ️提示 | 客户未填写编码 |
| 9 | 版本号格式检查 | ℹ️提示 | 版本号格式是否规范 |
| 10 | 日期范围检查 | ❌错误 | 开始日期晚于结束日期 |
| 11 | 分组成员重复 | ❌错误 | 同一分组内有重复客户 |
| 12 | scope 一致性检查 | ⚠️警告 | 重庆海尔/佳世达的 scope 是否符合业务规则 |

## 📝 常见操作

### 切换月份/版本

修改 `meta` 下的 `version`、`period_full`、`period_short`、`date_start`、`date_end`，然后重新生成 SQL。

### 新增寄售点客户

1. 在 `consign_points.transfer` 或 `consign_points.dispatch` 中添加客户
2. （可选）在 `group_mapping` 对应分组中添加成员
3. （可选）在 `qrcode_customers.customers` 中添加
4. 运行 `validate_config.py` 检查
5. 运行 `render_sql.py` 生成 SQL

### 新增集团分组

在 `group_mapping` 中添加：
```yaml
- group_name: "新分组名"
  members:
    - name: "客户1"
      scope: "both"
    - name: "客户2"
      scope: "both"
```

### 修改特殊开票备注

在 `invoice_rules.special_memo_customers` 中找到对应客户，修改 `memos` 列表。

## ⚠️ 注意事项

1. **客户名称必须与 ERP 客户档案完全一致**，否则查询不到数据
2. **版本号会影响表名**，切换月份时务必修改 version，避免覆盖旧表
3. **日期格式必须是 YYYY-MM-DD**，否则 SQL 执行会报错
4. **分组 scope 不要随意改**，特别是重庆海尔和佳世达的业务规则
5. 修改配置后建议先运行校验脚本，确认无误再生成 SQL
